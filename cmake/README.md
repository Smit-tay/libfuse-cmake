# The CMake build of this fork

This fork is upstream [libfuse](https://github.com/libfuse/libfuse) plus a
CMake build that produces the same result as upstream's meson build. The meson
files are kept, unchanged, both so upstream's own build still works and so the
CMake build can be checked against it.

What lives here:

| File | Purpose |
|---|---|
| `FuseConfigData.cmake` | meson's `configuration_data()` for CMake: writes `fuse_config.h` and `libfuse_config.h` in exactly meson's format |
| `fuse3.pc.in` | template for the installed pkg-config file, laid out like meson's `pkg.generate()` |
| `check-meson-parity.py` | builds the tree with both systems and compares the results |

CI: `.github/workflows/cmake.yml` is the fork's only addition to upstream's
workflows. It builds with CMake (gcc, clang, gcc `-m32`; unprivileged and as
root), fails on any warning, runs the test suite, and runs
`check-meson-parity.py --tests-as-root` for gcc and clang. Every other
workflow is upstream's, unchanged, and builds with meson.

Each `CMakeLists.txt` follows its `meson.build` section by section, with the
meson construct it mirrors named in a comment, so an upstream change to one
`meson.build` maps to one place in CMake.

## Syncing with upstream

1. **Fetch, and note the previous sync point** (needed in step 3):

       git fetch upstream
       OLD=$(git merge-base HEAD upstream/master)
       git switch -c upstream-sync-$(date +%Y%m%d)

2. **Merge** and resolve conflicts:

       git merge --no-ff upstream/master

   - Code, tests, docs, CI workflows: take upstream's version
     (`git checkout --theirs <file>`), then re-apply any warning fix of this
     fork that the conflict touched.
   - `README.md`, `requirements.txt`: keep the fork's CMake parts, take the
     rest from upstream.

3. **See what changed in the meson build** since the last sync:

       git diff $OLD upstream/master -- meson.build meson_options.txt '*/meson.build'

   and port each change to the matching section of the matching
   `CMakeLists.txt`. New meson options become `OPTION_<NAME>` cache entries in
   the top-level `CMakeLists.txt`, and get a row in the README's option
   table. New `private_cfg.set*()` calls become
   `fuse_cfg_set*(private ...)`.

4. **Build and fix warnings in the code.** The CMake build passes neither
   `-Wno-sign-compare` nor `-Wno-unused-result` (see below), so new upstream
   code may warn. Fix it in the source, never with a flag or a pragma;
   casting the signed operand to the type the comparison already converts it
   to keeps behaviour identical (use `uint64_t`, not `size_t`, for `off_t`:
   `size_t` is 32-bit on 32-bit systems).

5. **Check parity** with meson:

       cmake/check-meson-parity.py --tests              # unprivileged
       cmake/check-meson-parity.py --tests-as-root      # full suite, uses sudo

   For an option-dependent change, pass the option to both builds, e.g.
   `--meson-opt enable-custom-io=true --cmake-opt OPTION_ENABLE_CUSTOM_IO=ON`.
   `--cc clang --cxx clang++` and `--prefix /usr` are worth a run too. The
   script exits non-zero and says what differs if anything does.

6. **Commit** in three steps, so each can be reviewed (and the warning fixes
   offered upstream) on its own: the merge, the CMake port, the warning
   fixes.

## Deliberate differences from meson

These are the only differences `check-meson-parity.py` accepts:

- **Warning suppressions.** meson passes `-Wno-sign-compare`, and
  `-Wno-unused-result` on compilers that warn about a `(void)` cast of a
  `warn_unused_result` call. This build passes neither; the warnings are
  fixed in the code instead.
- **`-pthread`.** CMake's `FindThreads` adds no flag when pthreads live in
  libc (glibc 2.34 and later); the only thing `-pthread` still does there is
  define `_REENTRANT`, which both builds pass explicitly.
- **Generated header banner.** `fuse_config.h` and `libfuse_config.h` say
  "Autogenerated by the CMake build system" instead of "Meson".
- **Installed binaries' bytes.** Debug info records each build's paths and
  link layout differs; meson also overwrites a removed RPATH with `X`s in
  `.dynstr`, where CMake drops the entry. The script compares what the
  dynamic linker sees (SONAME, NEEDED, RPATH/RUNPATH) and the exported
  symbols instead.
- **Option names.** `OPTION_<NAME>` instead of meson's names; the README has
  the mapping.
- **Test registration.** `ctest` has the same two entries as `meson test`
  (`fuse-tests`, `fuse-tests-io-uring`), and `make check` builds then runs
  them; meson's `depends:` has no ctest equivalent.
